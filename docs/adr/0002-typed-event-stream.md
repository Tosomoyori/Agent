# ADR 0002：引擎只产出类型化事件，不返回值

**状态**：已采纳

## 问题

引擎跑完一次推理之后，结果怎么交给调用方？

## 选项

**A. 返回最终字符串。** 简单直接。要看中间过程就注册回调。

**B. 只产出类型化事件流。** 最终答复是最后一个事件里的字段。

## 决定

选 **B**。

## 理由

有**四个消费者**要看同一条流：

| 消费者 | 要什么 |
| --- | --- |
| CLI | 逐步打印进度、工具调用、审批提示 |
| SSE 端点 | 把事件转发给浏览器 |
| 可观测层 | 在事件边界上开关 span、累加用量 |
| 评测 | 按轨迹算「工具选对没有」「花了几步」 |

选 A 的话每个消费者各写一套回调，而且**回调里能看到的信息（token 级增量）
和返回值里的信息（最终文本）是两套东西**——它们是两个真相源，迟早不一致。

选 B 之后，这四件事都退化成「消费同一个流的不同姿势」。

## 代价

* 所有调用方都要 `async for`，多了一层缩进；
* 错误要建模成**事件**（`run_failed`）而不是异常。引擎内部必须把所有异常
  收敛成终止事件，否则消费者会挂住等一个永远不会来的结果；
* 调试生成器比调试函数难。

## 意外收获

把「追踪」变成了纯函数。`TraceBuilder` 是事件流的**消费者**，一行埋点代码都不用往
引擎里插——见 [`observability/tracer.py`](../../src/agentkit/observability/tracer.py)。
埋点式的成对调用（`span.start()` / `span.end()`）迟早会漏一处：返回值没接住、
异常分支没关，trace 里就出现永不结束的 span。
