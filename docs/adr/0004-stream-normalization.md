# ADR 0004：流式增量在适配器层归一化，而不是信任某一家文档

**状态**：已采纳

## 问题

流式响应里，工具调用的参数是怎么分片传过来的？各家不一样，而且文档基本不写。

## 选项

**A. 照文档/社区说法实现。** 查到的主流说法是「DeepSeek 的 `arguments` 是
**累积重发**：每个 chunk 重发目前为止的全部内容」。

**B. 先实测，再按实测结果实现，同时留兜底。**

## 决定

选 **B**。实测**证伪了 A**。

## 实测结果

```
片段 1: ''      片段 2: '{'      片段 3: '"'      片段 4: 'file'
片段 5: '_path' 片段 6: '"'      ...              片段 24: '}'
```

按顺序拼接得到合法 JSON，每个片段**不是**前一个的超集——是**真增量**。
复现脚本：[`scripts/capture_stream.py`](../../scripts/capture_stream.py)，
原始 chunk 存在 `tests/fixtures/`。

同一轮实测还发现三件文档没写的事：

1. **`id` / `name` 只在首个增量里出现**，后续 chunk 这两个字段**整个不存在**。
   所以它们是**赋值**语义，用 `+=` 会把 id 拼成一串垃圾。
2. **思维链占了输出 token 的绝大多数**。让模型「数到五，只输出数字」：
   1023 个 chunk 里 1013 个是 `reasoning_content`，正文只有 10 个 token，
   而 reasoning token 有 1012 个。
3. **usage 在最后一个 chunk，且那个 chunk 的 `choices` 是空列表**。
   把「choices 为空」当成「没有内容」跳过，就永远拿不到 usage。

## 决定的具体内容

* 拼接用增量语义（实测结果）；
* 但 `join_argument_fragments` **保留累积重发的兜底**：拼出来不是合法对象时，
  试「取最长片段」这条退路，并把走了退路这件事记进备注。

保留兜底的理由：这是**服务端实现细节**，没有契约保证它不变；而写错的代价
（参数静默变成 `{}`，工具收到空参数）比多写十行兜底代码严重得多。
**静默地做对，比做错了还让人放心不下**——所以走了退路要留痕。

## 代价

* 要维护一份「provider 行为表」，provider 改协议要跟进；
* 实测出来的结论有时效性——`docs/provider-notes.md` 里标了测量日期，复查时先重跑脚本。

## 未使用 SDK 直接解析的原因

SDK 给的是 raw delta，**不做语义归一化**。它不知道 `id` 是赋值而 `arguments`
是追加，也不知道 usage 可能藏在一个 `choices` 为空的收尾 chunk 里。这些判断
必须由适配器做。
